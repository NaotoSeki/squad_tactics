## 2. Step 1 — 対象の同定(ローカル証拠)

「Panzer Strike」がどの作品を指すかをまず確定する。ローカルの手がかり:

- `scratch/kb3d_study/ps_reference/` — 抽出済み参照PNG 33枚
- `tests/test_ps_ssc_format.py` — 「SSC format」の検証テスト(PS素材抽出系のフォーマット)
- `scripts/` 内の ps_ 関連スクリプト(あれば)
- `C:\Users\aware.梨花のPC\Downloads` 配下にゲーム本体・データ・マニュアルが無いか(ファイル名検索のみ。**実行禁止**)
- 注意: `data/pl_*` / `wpns_pl_stats_decoded.json` は別系統(PL系武器データ)の可能性が高い。**Panzer Strike と混同しない**。由来が確認できた場合のみ言及。

有力仮説は SSI『Panzer Strike!』(1987, Gary Grigsby, Apple II/C64)。Grigsby系は「兵器データテーブル駆動・詳細な命中/貫通・士気/抑圧・指揮範囲」の設計で文書化が多い。ローカル証拠が別作品を指すならそちらに従う。

## 4. Step 3 — 成果物の構成(必須アウトライン)

成果物mdは次の構成で書く:

1. **対象の同定** — ローカル証拠と外部情報の突合。確度も書く
2. **全体アルゴリズムの解剖**(推測は推測と明記):
   - ターン/フェーズ構造(命令→解決、同時/交互、インパルス制)
   - 射撃解決(命中率の構成要素、貫通vs装甲、距離減衰、テーブル駆動の度合い)
   - 士気・抑圧(pin/rout の状態遷移、回復条件)
   - 視認・隠蔽(spotting、射撃による暴露、夜間/煙)
   - 指揮系統(指揮範囲、命令遅延、リーダー損失) ← **NORTH_STARの伝達コストに直結。最重要**
   - 経験・ベテラン化(キャンペーン引き継ぎ)
   - シナリオ/キャンペーン生成(戦力・マップのバリエーション付け)
3. **squad_tactics への移植候補(優先度付き)** — 「何を・どのファイル/システムへ・どの粒度で」。30hexビネット規模で効くものを優先
4. **頂戴しないもの** — 理由付き(帳簿過多、粒度違い、現代の遊びやすさと衝突 等)
5. **出典一覧**

## 2026-08-01 追加実装（本番ビュー検証済み）

- 最終確認URLは **`http://localhost:8788/`**。`127.0.0.1` は別オリジンであり、`sim_battle.html` 単体だけを合格判定に使わない。
- 手動Actionの射撃は旧AP判定を通さず、RTwP側の対象指定命令へ変換する。本番入口で「兵士選択 → 射撃 → 敵兵選択 → 命令ログ」まで確認済み。
- 発射イベントは `roundsFired` を持ち、実弾数の消費・銃口光の回数・ログの `xN` を一致させる。遮蔽で発射できない場合は弾を消費しない。
- 弾倉は `WPNS.cap` を実弾数として扱う。現在の基準総弾数は M1=8×(装填済み1+予備6)=56発、MG42=50×(装填済み1+予備4)=250発。
- 停止中の兵士は射撃対象へ向き、銃口座標から控えめな発光を出す。射線ラインは本番・検証ビューとも廃止。立体物は専用影がない場合に本体アルファから影を生成する。
- PS農村盤面は **12列×10段・120hex**、論理背景 **1600×1000**（実画像3200×2000）へ拡張した。横長の地面にしたことで、黒い盤外を露出せずにさらに俯瞰でき、左右へカメラ移動できる。
- 小銃の着弾は64pxの固定的な煙を廃止し、384px・8フレームの3種類を小さく再生する。`roundsFired` と着弾アニメ数を一致させ、命中弾と散布弾を同じ発射間隔で表示する。
- 本番の配置兵へsimスナップショット（`engageTargetId`を含む）を毎同期し、命令伝達中はpending targetを先に向きへ反映する。手動Actionも命令受付直後から対象方向を向き、配達後に同じRTwP射撃へ入る。
- 待機モーションのフレーム間引きをやめ、stand/kneel/prone idleは元の全フレームを使う。PS立体物は実際に描画される配置がすべてAI生成2x HDへ解決しており、低解像度canonicalへの描画フォールバックは0件。縮小時はLINEARフィルタを明示する。
- `phaser_alpha_light.js` を共通アルファ光空間として追加。建物・木・兵士の現在フレームを黒いアルファ減光マスクへ変換して左上太陽光の投影影を作り、マズル閃光時は同じアルファ形状へ暖色輪郭光と光源から反対方向の短時間影を生成する。個別の楕円影・物体専用リム処理へ分岐させない。MULTIPLY 合成は明るい地面で視認性が不安定なため使わず、通常のアルファ合成で背景輝度を確実に落とす。
- PS立体物の影は root の負depthへ置くと `hexGroup(depth 0)` の地面レイヤー全体に隠れるため、地面・道路より上かつ立体物本体より下の専用影レイヤー(depth 8.5)へ収容する。焼き込み接地影、生成アルファ太陽影、マズル光の逆向き短時間影を同じレイヤーに載せる。
- 一時停止を `phaser_tactical_pause.js` の戦術判断モードへ変更。マップ全体をグレー化し、全兵士の「移動・照準/射撃・再装填・制圧・待機」、対象への矢印、選択兵のHP/制圧/弾薬を表示する。停止中も味方選択→敵クリックで個別射撃、右クリックで移動、F/S/Cの分隊命令を発行でき、命令は再開後に通常のCommsOrders経路で配達される。
- 左上にクリック移動可能な戦術ミニマップを追加した。現在の主画面範囲を黄色い枠で示し、広い盤面の全容と現在地を同時に確認できる。
- 写実兵の方向manifestは `S,SE,E,NE,N,NW,W,SW` を画面方向へそのまま対応させる。以前は行番号を反転していたため、横・斜め向きが逆だった。銃口起点も足元原点から姿勢別の肩・銃身高へ持ち上げた。
- 選択兵の右ペインに `RTWP AMMO 弾倉/容量 +予備（弾倉数）` をライブ表示する。sim内部では `roundsFired` だけ弾倉を減らし、弾倉が空なら発射イベントを出さない。
- 戦闘中にカードから配置した兵士も、そのフレームでRTwPへ登録する。初期配置と同じ武器・弾薬・AI・被弾処理へ参加し、分隊長は重複させない。本番URLでBilly Williamsをカード配置し、直後のSTATEと射撃ログ（`SHOT Billy Williams->Gunner ... x15`）まで確認済み。
- 変更範囲の受入: `rtwp_battle` 41件、`sim_core` 18件、音/カメラ54件、農村マップ/カメラ境界、PS地面生成ほか合格。全体実行では未変更の `map_city.test.js` に既存診断1件（seed 0）が残る。

## 2. RTwP化の現状

### 2.1 何がどう入っているか

NORTH_STAR §7 Strangler Fig。**`logic_game.js`（2133行）は一行も書き換えていない。**

```
index.html（?rtwp=0 で旧ターン制へ完全復帰）
   └─ phaser_bridge.js MainScene.update()
        ├─ RtwpBattle.attach(gameLogic)        ← 初回のみ
        └─ RtwpBattle.instance.update(delta)   ← 毎フレーム
              ├─ sim.tick() を最大5回/frame（固定100ms）
              ├─ LeaderPolicy.assess() → sim.issueOrder()（伝達遅延あり）
              ├─ drainEvents() → VFX / Sfx / ui.log
              └─ syncUnits(): sim の q,r,hp,suppression を **units へ書き戻す**
```

**接ぎ木の要**: `phaser_unit.js` の `UnitView.update()` は毎フレーム `gameLogic.units` を
走査して `q/r/hp` から描画を同期する。だから units へ書き戻すだけで既存描画が追従する。
新しい描画コードは要らない。ここが崩れると全部崩れる。

UI は `gameLogic` の**インスタンスメソッドを包む**方式（クラスは触らない）:
右クリック=移動命令 / END TURN=一時停止トグル / Space=停止 / 1,2,3=速度 /
F=集中射撃 / S=制圧射撃 / C=遮蔽に入れ。`RtwpBattle.detach()` で元の実装とHUDが完全に戻る。

### 2.2 検証済みのこと

- `tests/rtwp_battle.test.js` 27件（CityMap 400hex 上で sim が回り units へ書き戻る、
  命令の形 `{type, soldierIds, payload}`、経路が1hexずつ刻まれる、決着後停止、detach復元）
- 本編の実モジュールを読んだページ内で `attach` 成功・8名が3000tick交戦・`ui.log` へ出力
- UI配線をブラウザで確認（右クリックが移動命令へ回り元実装は呼ばれない、detachで復元）

### 2.3 **未検証のこと（最重要）**

> **実際にキャンペーンを開始して RTwP が動いている絵を、誰も見ていない。**

前任の環境はブラウザペインが非表示だと RAF が抑制され、セットアップ画面
（SQUAD RECRUITMENT）から戦闘を起動する自動操作が安定しなかった。

**Codex への最初の依頼**: ブラウザで `http://localhost:8788/` を開き、兵士を選んで
DEPLOY し、**実戦闘で以下を目視確認すること**。ここが通らない限り先へ進まない。

1. `window.RtwpBattle.active === true` になるか
2. 兵士が実時間で動き・撃ち・伏せるか（ターン待ちが無いか）
3. 左下に RTwP のHUDが出るか、Space で止まるか
4. 右クリックで移動命令が通るか
5. コンソールにエラーが出ていないか

不具合が出たら `?rtwp=0` で即座に旧ターン制へ戻せる。**戻せることが保証されているので、
壊れても慌てないこと。**

### 2.4 既知の未対応

- **戦車**: 武器解決できないユニットは登録をスキップする（`unit._rtwpSkipped = true`）。
  RTwP戦闘では戦車が動かない。
- **AP表示**: サイドバー(`logic_ui.js`)に AP が出たままだが RTwP では無意味。
- **キャンバスが `#game-view` の寸法に追従しない**（**RTwP化以前からの既存挙動**。
  一度 stash して元実装で再現確認済み）。`game-view` が 1280x720 でもキャンバスが
  128x128 のまま。実際に遊んで画面が小さい/ボケるなら、まずここを疑う。
  高DPI対応(`Renderer.RENDER_DPR`)はこの理由で**入れていない**（受け皿だけ置いてある。
  常に1＝無効。キャンバスのリサイズが直れば値を入れるだけで効く）。
  sim_battle.html では同じ対応が実効（dpr=1.5 で画素数2.25倍・視野不変・61fps維持）。

## 5. リファクタの進捗と次の一手

原則: **動いているものを止めない。** 「新モジュールへ切り出して旧を残す」→
「呼び出しを移す」→「旧を消す」の3段で、各段でテストを通す。

`tests/combat_rules.test.js` 27件。委譲後と移設元を**91ケースで突合し不一致0件**。

**この型を守ること**: 移設したら必ず「委譲後の実装」と「フォールバック（＝移設元と
同一コード）」に同じ入力を与えて出力一致を証明する。挙動を1ミリも変えない。
ロジックの改善・変数名の整理・早期returnへの書き換えは**リファクタと混ぜない**。

対象選定は勘でなく `python scripts/profile_methods.py` で（97メソッドを行数・

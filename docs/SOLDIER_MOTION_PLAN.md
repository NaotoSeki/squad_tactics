# 兵士モーション拡充計画 — 戦争映画品質への3層アーキテクチャ

2026-07-20 起草。兵士スプライト動作の拡充・シームレス化の正本。
関連: [NORTH_STAR.md](NORTH_STAR.md) / `asset/sprites/soldier/` / `scripts/soldier_pipeline/` / `phaser_soldier_view.js`

## 0. ゴールと評価軸

ジオラマ神視点（20px級表示）のまま「戦争映画さながら」の兵士アクションを成立させる。
戦争映画感は次の4軸に分解して攻める:

1. **語彙** — 動きの種類（現19モーション）を戦闘文脈込みで拡充する
2. **接続** — 任意のアクション切替がポップしない（シームレス）
3. **文脈** — 遮蔽・被弾・制圧に応じた変種（塀から身を乗り出して撃つ等）
4. **生体感** — 個体差・非同期（全員が同じ位相で息をしない・撃たない）

制約（ブラウザ限界）: テクスチャVRAM予算 230MB（repack v2の検証上限）、1シート ≦ 8192px、
Phaserのスプライトはランタイムでボーンブレンドできない。

## 1. 結論: シームレスは「ベイク時に」解決する

実行時ブレンド不能はスプライトゲーの宿命だが、本作は3Dソース（Blender + mixamorig）を
持っているので、繋ぎを**焼いて**しまえる。3層アーキテクチャ:

### L1 ベイク層（Blender / scripts/soldier_pipeline/）
- **遷移クリップ自動生成**: 同姿勢のアクション対（fire↔idle 等）について、境界ポーズ間を
  四元数slerp+smoothstepで6〜10フレーム補間したクリップを機械生成しシート化する。
  Mixamoに遷移クリップが存在しなくても任意対を自給できる。
  （異姿勢間は既存のMixamo実遷移 stand↔kneel↔prone を使う。ポーズ距離が大きい対の
  機械補間は貫通・足滑りが出るため対象外）
- **ループ閉包**: idle/forward系の終端Kフレームを先頭ポーズへブレンドし、ループのポップを消す
- **新規クリップ取込**: MixamoのFBXをドロップフォルダから一括インポート→アクション改名→レンダ

### L2 ランタイム層（Phaser / phaser_soldier_view.js）
アクション切替時の3段フォールバック:
1. ベイク済み遷移シート `trans_<from>__<to>` があれば再生してから目標アクションへ
2. 無ければゴーストスプライト（旧アクション最終フレーム）を約90msでα0へ→クロスフェード
3. 最終手段ハードカット（従来挙動）

加えて:
- **方向転換のステップ化**: 8方向スナップをやめ、45°ずつ数tick刻みで回頭（射撃目標へは即応スナップ）
- **個体desync**: ループ再生の開始位相をユニットIDハッシュでずらす+再生速度±8%ジッタ
- **変種選択機構**: `cover_fire` 等の変種シートが manifest に存在すれば自動で優先使用
  （アセットが届いた瞬間に有効化される。コード変更不要）

### L3 文脈層（ゲームロジック）
- 遮蔽中の射撃 → cover_fire 変種+ヘックス縁（射線方向）への寄りオフセット+銃口炎位置補正
- 被弾 → フリンチ one-shot（クリップ到着まではクロスフェード+姿勢一段下げで代用）
- 制圧 → cower 変種（現状は kneel/prone 代用中）
- 将来: 分隊躍進（bounding overwatch）等の分隊振付は sim_leader 側の仕事とし、本計画の範囲外

## 2. 「Mixamoリグの限界」への回答

リグ（mixamorig 33ボーン）自体は標準的で問題ない。限界の実体は
①クリップ間の繋ぎが提供されない ②カバー・軍事系の語彙が薄い、の2点。

| 課題 | 解決レーン | 状態 |
|---|---|---|
| 繋ぎが無い | L1遷移ベイクで自給 | 本計画で実装 |
| カバー語彙が薄い | クリップ追加 + Blender手調整（spine回転でlean変種を自作） | フェーズ2 |
| それでも無い動き | Cascadeur等で自作アニメ | 最終手段（当面不要） |

## 3. パイプライン（scripts/soldier_pipeline/）

ワンコマンド増分ビルド: `python scripts/soldier_pipeline/sp_pipeline.py`

```
master blend（sprite_sheet_multi_motions_2.blend、不可侵）
  → work.blend へコピー
  → sp_import_fbx.py   : ドロップフォルダのFBX一括取込（アクション改名・ボーン整合検証）
  → sp_bake_transitions.py : transitions.json の指示で遷移生成+ループ閉包
  → sp_synth_clips.py  : synth_clips.json の指示でアーマチュア直接操作による新規クリップ合成（§7）
  → sp_render_frames.py : SpriteCamで 400×262 × 8方向 × フレームを増分レンダ
  → sp_compose_sheets.py : PILで 列=フレーム/行=方向 のシートへ合成（旧シートと同一レイアウト）
  → repack_soldier_sheets_v2.py : クロップ・スケール正規化・manifest v2 再生成（既存流用）
```

検証ゲート（反ハッタリ）:
- **パリティテスト**: 新レンダの stand_idle f1 × 8方向 を旧シートのセルと画像diff
  （カメラ・方向行順・スケールの同一性を機械証明。合格するまで新旧シート混在禁止）
- repack組込の manifest整合・方向多様性md5・VRAM上限チェック

## 3.5. 自給できる動きとDLが必要な動きの線引き（2026-07-30 確定）

`sp_synth_clips.py`（§7）の導入で、**既存19モーションの組み替えで作れる語彙はDL不要**になった。
線引きは「必要な関節軌道が既存クリップの中に在るか」で決まる。

| 動き | 自給可否 | 手段 |
|---|---|---|
| 物陰に潜む（壁貼り付き） | ✅ 自給 | Idle を hold + 脊椎を屈曲 offset |
| 物陰から乗り出して射撃 | ✅ 自給 | Fire に**ロール(Z)** offset。ピッチ主導は不可（照準が壊れる） |
| 撃ってまた隠れる | ✅ 自給 | 上2つを端点にした splice 遷移（往復2本） |
| 飛び込み伏せ・回避 | ✅ 自給 | `Stand_To_Kneel`+`Kneel_To_Prone` を splice → retime 圧縮 |
| 制圧下で縮こまる | ✅ 自給 | Idle を hold + 強めの屈曲 offset |
| 被弾フリンチ | ✅ 自給 | Idle に pulse エンベロープで後方インパルス |
| **リロード（立ち）** | ✅ DL済(2026-07-30) | `Reloading.fbx`。元々インプレース（全軸ドリフト≈0を実測） |
| **リロード（膝立ち/伏せ）** | ✅ 自給 | 立ちリロードの上半身を `graft` で各姿勢の土台へ移植 |
| **走り** | ✅ DL済(2026-07-30) | `Rifle Run.fbx`。**In Place無し**なので `strip_root_motion` 必須 |
| **しゃがみ走り** | ✅ 自給 | 走りの上半身を `Kneel.Forward` の脚へ `graft` |
| 乗り越え・負傷歩き・合図 | ❌ DL必須 | 元軌道が無い。当面は未着手 |

優先度Aは**全て解消**した。DLしたのは実質2本だけで、姿勢違いは `graft` で自給している。

## 5. レンダ較正の正（2026-07-20 実測確定）

旧19シートのレンダパラメータは保存されておらず（カメラ2台とも現状値では不一致）、
数値解析で復元した。**この値が今後の全レンダの正**（config.json の render_args）:

- カメラ: `SpriteCam`（loc (0,-5,1.2), rot X=80° — 仰角約10°の低目線）に
  **`--ortho-scale 4.67 --shift-up 0.43`** を適用 → 旧シートと bbox 1px 一致
- 方向回転: **`--rot-sign -1`**（時計回り）。行順は
  **0=SE, 1=S, 2=SW, 3=W, 4=NW, 5=N, 6=NE, 7=E**（2026-08-03 シルエット実測で確定）。
  回転の向き（時計回り）はこの記述で合っていたが、**起点が45°ずれていた**
  （「0=S」と書かれていたが実際の row 0 は SE）。`manifest.dirOrder` の旧値
  `S,SE,E,...` はさらに鏡像で、どちらも誰も測っていない値だった。
  正本は `tests/test_soldier_dir_order.py` が実シートのピクセルから検証する（prone 8方向の目視で確認済み）
- セル 400×262 / 列=フレーム / 行=方向 / Eevee / 透過背景
- 注意: 旧シートとのピクセル完全一致は不可能（シートレンダ後にアクションデータが
  変化していた）。よって 2026-07-20 に**全シートを新パイプラインで再生成**し自己整合させた。
  旧シートは sheets_dir/archive_pre_pipeline_20260720/ に退避
- repack は `--char-h 72`（旧108）: 表示は manifest.charH 正規化で不変、VRAM を約半減し
  フェーズ2の増枠を確保（表示20px基準で3.6倍オーバーサンプル維持）

## 7. クリップ合成レーン（`sp_synth_clips.py` / `synth_clips.json`）

2026-07-30 追加。**アーマチュアを直接操作して既存アクションから新規クリップを作る**レーン。
`sp_bake_transitions.py` のポーズ入出力プリミティブ（`sample_pose`/`write_pose`/`blend_pose`/
`slerp_q`）を import して再利用しており、二重実装は無い。

### 演算子

ポーズ列 = `list[bone -> (location, quaternion)]`。`source`（単一クリップ）または `splice`
（複数クリップ + slerpブリッジ）で列を作り、`ops` を記載順に適用する。

| op | 用途 | 主パラメータ |
|---|---|---|
| `retime` | 速度変更・尺の圧縮 | `rate` または `frames` |
| `offset` | ボーン加算回転（lean/twist/屈曲の本体） | `bones`（度数XYZ）, `space`, `envelope` |
| `root` | 位置オフセット（弾道・寄り） | `bone`, `translate`, `envelope` |
| `hold` | ポーズ固定（+`breathe` で微動） | `frames`, `at`, `breathe` |
| `strip_root_motion` | In Place無しDLの前進成分を除去 | `bone`, `axes`, `mode`(`linear`/`lock`) |
| `graft` | 別クリップの一部ボーンを移植 | `from`, `bones`(`upper`/`lower`/配列), `step` |

`graft` が効くのは mixamorig の上下の切れ目が綺麗だから。**立ちリロード1本から
膝立ち/伏せ版を導出できる**ので、姿勢ごとにDLする必要がない。
上半身 = `Spine*`/`Neck`/`Head`/`*Shoulder`/`*Arm`/`*ForeArm`/`*Hand*`、
下半身 = `Hips`/`*UpLeg`/`*Leg`/`*Foot`/`*Toe*`（腰の向きは土台側が持つ）。

エンベロープは `const` / `ramp_in` / `ramp_out` / `ramp` / `pulse`。重みは恒等回転からの
slerp で効かせるので、途中の重みでも破綻しない。

**先に定義したクリップを後続クリップの入力にできる**（遮蔽ポーズ → その往復遷移を1ファイルで
書ける）。禁止しているのは自己参照のみ。

### 軸較正（実測。推測で書かないこと）

`Spine`/`Spine1`/`Spine2`/`Neck`/`Head` のローカル軸は **X=前傾ピッチ / Y=捻り /
Z=右肩側へのロール**。軸間クロストークはほぼ0（X操作時の横変位 ≤0.001）。
`Hips` だけは軸が混ざるので lean には使わない。肩・腕は体軸非整列かつ**小銃の保持が崩れる**
ので触らない。

### 踏んだ罠（2枚のレンダで実際に外した。再発防止は `tests/test_soldier_synth_clips.py`）

1. **角度を「頭部の変位量」から見積もると必ず過大になる。** 脊椎チェーンのピッチは視覚的に
   複合する。累積30°の前傾は「壁に隠れる」ではなく「崩れ落ちる」絵になった。
   落とし所は累積ピッチ Cover_Idle ≈12°(+頭8°) / Cower ≈21°(+頭12°) / Cover_Fire ≤5°。
2. **乗り出しはピッチではなくロール(Z)で作る。** ロールは小銃を肩付けしたまま横へ出るので
   照準の絵が保たれる。ピッチを足すと構えが解けて**改善ではなく劣化**になる。
3. **被弾フリンチを `*.Dying` から切り出してはいけない。** Dying は初動で小銃を手放すため、
   掠っただけで銃を投げ捨てる絵になる。代わりに Idle へ `pulse` で後方インパルスを与える
   （手のボーンを触らないので小銃は握ったまま）。
4. **レンダ job の `step` は必ず 1。** 合成側で既に間引いているため、二重間引きになる。
5. `defineAnimations()` のループ判定は語尾正規表現。新語彙を足すときは
   「持続状態＝ループ」「一回性＝非ループ」の分類を確認する
   （`_cower`・`_run` はループ側、`_reload` は非ループ側。リロードをループさせると
   弾倉を何度も入れ直す絵になる）。
6. **In Place を付け忘れたMixamoクリップは実際に前進する。** `Rifle Run` は Hips の
   local Z が 21フレームで +289 単調増加していた（X/Yは往復＝ボブ）。`strip_root_motion`
   の `linear` で先頭→末尾の直線ドリフトだけ抜けば、上下動を残したままループも閉じる。
   抜き忘れると兵士がセルの外へ歩いて出ていく。
7. **骨名一致率の分母に注意。** Mixamo配布FBXはマスターより指骨が多い
   （Middle/Pinky/Ring/Thumb を持つ）。分母を `max(master, imported)` にすると
   完全互換なのに 50.8% と判定されて取込拒否される（2026-07-30 実例）。
   分母は**マスター側の可動骨（リーフ骨を除く）**。リーフ骨は `ignore_leaf_bones=True`
   で落ちるので評価から外す。修正後は両クリップとも一致率 1.0。

## 6.5. L3文脈層の発火条件（2026-07-30 時点）

アセットは manifest 駆動で自動ロードされるが、**いつ出すか**は別途配線が要る。現状:

| アクション | 発火条件 | 実装 |
|---|---|---|
| `<姿勢>_cover_fire` | 遮蔽値 ≥ 0.3 かつ射撃中 | 済 |
| `<姿勢>_cover_idle` | 遮蔽値 ≥ 0.3 かつ非射撃 | 済 |
| `<姿勢>_cower` | `pinned` 相当の重制圧 | 済 |
| `<姿勢>_hit` | 新規被弾の検知（one-shot） | 済 |
| `stand_dive_prone` | 被弾中に stand→prone の二段落ち | 済 |
| `<姿勢>_reload` | `s.state === 'reload'` | 済 |
| `<姿勢>_run` | 実効移動モードが `rush`（+ 旧経路の「被弾中の移動」） | 済（2026-08-03 実接続） |

### 走行トリガ（2026-08-03 改訂。旧「被弾中の移動だけ」は解消）

sim は `MOVE_MODE_MULT { walk:1, rush:0.5, crawl:2.5 }` で歩/走/匍匐を持ち、
プレイヤーの命令は「移動」1つ（`mode:'auto'`）のまま、**1マスごとに
`TraitPolicy.pickMoveStep` が渡り方を決める**（撃たれている→匍匐 / 見られている
開豁地→走り / それ以外→歩き）。切替は完全に自動で、語彙の追加は要らない。

**接続の要点は「実効モードをスナップショットへ出す」こと。** 生の `s.moveMode` は
移動中ずっと `'auto'` に据え置かれるので、描画が `moveMode === 'rush'` を見ている
限り走行シートは**一度も選ばれない**（2026-07-30 にシートを焼いてから 2026-08-03
まで、実は一度も表示されていなかった）。`SimCore._snapshot` が
`stepMode`（= `_effectiveMoveMode`）と `observeT` を出し、
`SoldierUnitView._effMoveMode / _isRunning` がそれを読む。

| 実効モード | 出る絵 | 備考 |
|---|---|---|
| `walk` | `<姿勢>_forward` | 遮蔽伝いの前進 |
| `rush` | `<姿勢>_run` | 伏せ姿勢には走行シートが無いので `prone_forward` へ自動フォールバック |
| `crawl` | `prone_forward` | sim が `s.prone` を立てるので姿勢側で伏せになる |
| （`observeT>0`） | `kneel_*` | 開豁地へ出る前の様子見は最低でも膝立ち＝屈んで窺う絵 |

**スプライトの滑走速度もモードに追従させた。** 以前は `0.9px/frame` 固定で、
ヘックス間隔 √3·HEX_SIZE ≈ 93.5px に対し歩き(0.8秒/hex ⇒ 約1.95px/frame)にすら
追いつけていなかった — 走らせても絵だけ速く位置が置いていかれる。
`UnitView._infantryStepPx` が sim の所要時間から逆算する。snapshot がまだ届いていない
初期描画だけは一定速度を使う。

**速度の正本は `stepTicks`（スナップショット）。** モード倍率だけから概算すると、
重い地形（`moveCost`）や脚の遅い兵（`ATTR_SPD_RANGE`）で**スプライトが先に着いて待つ** —
歩行アニメが途中で idle に落ちてカクつく。`SimCore._actMove` が実所要tick
（`MOVE_T_PER_HEX × 地形コスト × モード倍率 × 脚の速さ`）を publish し、描画はそれを使う。

### 6.5.1 重み（2026-08-03 ディレクター指摘「重みが感じられない」）

**① 基準速度を落とした**: `MOVE_T_PER_HEX 8 → 12`。地形コスト1・能力等倍で
歩き1.2秒/hex(78px/s)・走り0.6秒/hex(156px/s)・匍匐3.0秒/hex(31px/s)。
**ここは戦術の値でもある**（開豁地を渡る間に浴びる弾数がそのまま増える）。
見た目だけ遅くしたくてもこの値を単独でいじらないこと — 描画は所要時間から逆算しており、
片方だけずらすと兵士が論理位置から千切れる。

**② 歩調の上下動（サイン波）を足した**: `SoldierUnitView._gaitBob`。
実測の裏付けが設計を決めた —— **`stand_forward` は頭頂の変位が全14フレームで0px**、
つまり歩きには元々まったく縦の動きが無かった。`stand_run` は6px(シート空間・表示換算1.7px)
持ち、**谷が p=0・山が p=0.25**。そこで同位相のサイン波（`-cos(2π·2p)`、1ループ＝2歩）を
足して増幅する。逆位相にすると打ち消し合って、上下しているのにぼやけて見える。
振幅は表示20px基準で 歩き±0.8px / 走り±1.3px、匍匐と姿勢遷移と静止は0。

**罠: 影を先に作ってから上下を足すこと。** `AlphaLightSpace.syncSunShadow` は
`source.x/y` を読むので、上下を乗せた後に呼ぶと影まで一緒に跳ねて足元が浮く。
`_syncShadowTex` は「接地位置で置く → 影を作る → 本体にだけ上下を足す」の順。
実機実測で影の変位0px を確認済み（乗り出し `COVER_LEAN_PX` は従来どおり影も動く
—— 体が実際に横へ出ているので、これは正しい）。

**位相はクリップの再生位置に固定する**（時間で回すと足の接地とずれ、足が着いた瞬間に
体が浮く）。`currentFrame.index`（Phaser は1始まり）から算出。`getProgress()` は
バージョンで量子化仕様が変わるので使わない。

受入テストは `tests/soldier_run_motion.test.js`（49件。sim の契約・アニメ選択・滑走速度・上下動）。

### 6.5.2 向き — 「後ろ歩き / 撃つ方角を向かない」（2026-08-03）

ディレクター指摘。**原因は5つ。** 最初に4件を潰した後、実プレイのPAUSE画面で
「撃ち合う二人が完全に互いの逆を向く」が残り、それが**最も根深い5件目**だった。
受入テストは `tests/soldier_facing.test.js`（19件）＋ `tests/test_soldier_dir_order.py`（5件）。

#### 5件目: シートの行順そのものが間違っていた（最重要）

`manifest.dirOrder` と `soldierDirFromDelta` は行順を `S,SE,E,NE,N,NW,W,SW` としていたが、
**実物は `SE,S,SW,W,NW,N,NE,E`** —— 鏡像かつ45°ずれていた。旧値は
repack_soldier_sheets_v2.py のハードコード文字列で、**誰も測っていなかった。**

**この種のバグは自己整合するコードでは絶対に検出できない。** 実際、直前の実機計測で
「射撃方向の一致 2084件中ミス19（99.1%）」と出ていたが、期待値をコードと同じ式で
出していたため、規約ごと間違っていても一致してしまっていた。

実測の根拠（`prone_idle` / `stand_fire` / `kneel_fire` で一致）:
- シルエット幅が最小なのは row 1,5（視線軸＝N/S）、最大は row 3,7（横向き＝E/W）。
  **カーディナルが奇数行に来る**ので「row 0 = S」は原理的にありえない。
- 伏せて奥を向く(N)方が手前(S)より画面上で背が高い → N/S を確定。
- **重心は常に狙いの反対側へ寄る**（脚と胴が後ろに残る）→ 左右の別を機械判定できる。
  幅・高さは鏡像で不変なので、handedness を固定できるのはこの符号だけ。
  例外は `stand_idle`（銃を下ろしていて前方への張り出しが無い）ので検証対象外。

**検証の鎖を二段にした**（自己参照を断つ）:
`tests/test_soldier_dir_order.py` が `manifest.dirOrder` を**実シートのピクセル**へ、
`tests/soldier_facing.test.js` の F0 が `soldierDirFromDelta` を `manifest.dirOrder` へ突き合わせる。
`tests/sfx_and_camera.test.js` の期待値直書きも撤去した（それ自体が誤順序を固定していた）。

#### 残り4件（取得元と回頭速度）

| # | 症状 | 原因 | 対処 |
|---|---|---|---|
| 1 | 反転時に後ろ歩き | 回頭が状況を問わず 45°/3tick。180°に0.9秒＝**0.75ヘックスぶん**歩く間ズレたまま | 移動中は `MOVE_FACE_MAX_LAG`(45°)を超えるズレを待たずに詰める。静止時の45°刻みは維持 |
| 2 | その場で回れ右 | 移動中の向きを**画面のピクセル差分**から取っていた。同居ユニット数が変わると `_calcUnitOffset` が組み替わって全員が横滑りし、それを移動方向と誤読 | `_moveFacing` が **sim の `s.facing`**（いまアニメートしている step の向き）を正本にする |
| 3 | 面制圧で明後日を向く | `TARGET_HEX` は `engageTargetId` が null。撃つ地点を向く根拠がどこにも無かった | `s.engageHex` を方向源に追加（個体標的の方が優先） |
| 4 | 狙っている相手を向かない | `visuals` のキーは**数値**、`engageTargetId` は**文字列**。旧フォールバックの `/^\d+$/` は小数を弾くので、本編(`Math.random()` 由来の小数ID)では**この分岐が一度も成立していなかった**（`sim_battle.html` は文字列IDなので露見しない） | `_visualById` で数値/文字列/小数を吸収 |

**倒れた兵が匍匐しはじめる問題も同根。** `isMoving` は「画面上で滑っているか」でしかないので、
散布オフセットの組み替えで incap の兵まで `prone_forward` を再生していた（実測で移動サンプルの10%）。
`_canLocomote` で `incap`/`down`/hp0 を除外する。**`state === 'move'` では判定しない** ——
スプライトは最大1ヘックスぶん遅れて追走するので、経路の最後で本当に歩いている兵まで idle に落ちる。

実機実測（`index.html`・全4件適用後）: 移動中の向き **68/68 一致（後ろ歩き0）**、
面制圧 **143件ミス0**、個体標的 **2084件中ミス19（99.1%）**、倒れた兵の移動アニメ **0件**。
残る0.9%は標的を切り替えた直後の45°ステップ回頭（静止時の意図した挙動）。

## 6.6. 自動Cover（反射）— sim_policy.js

`TraitPolicy.decide()` に自発退避を追加（2026-07-30）。**プレイヤー命令とは競合しない** —
`sim_core` は `currentOrder` があれば `decide` を呼ばないので、これは「命令が無いときの
自己判断」だけに効く。

発火帯は制圧 `[COVER_SEEK_AT(50), PINNED_AT(80))`。現在地の遮蔽が `COVER_SEEK_MAX_COVER`
未満なら、隣接で最も濃い遮蔽へ `MOVE_TO` する。`COVER_SEEK_MIN_GAIN` 未満の改善では
動かない（わずかな差で右往左往させない）。PINNED 以上は伏せたまま動かない
（頭を上げられない状態で開けた地面を走るのは自殺）。
`timid` は竦んで動かず、`cautious` は `MIN_SELF_MOVE_COVER` 未満の遮蔽へは退避しない。

受入テストは `tests/sim_policy_cover.test.js`（13件）。

**未着手**: 指示によるCover（「あの塀まで前進して制圧射撃」）は `CommsOrders` の
語彙拡張になり、North Star の伝達コストと直結する。本計画の範囲外。

# 兵士モーション拡充計画 — 戦争映画品質への3層アーキテクチャ

2026-07-20 起草。兵士スプライト動作の拡充・シームレス化の正本。
関連: [NORTH_STAR.md](NORTH_STAR.md) / `asset/sprites/soldier/` / `scripts/soldier_pipeline/` / `phaser_soldier_view.js`

## 0. ゴールと評価軸

ジオラマ神視点（20px級表示）のまま「戦争映画さながら」の兵士アクションを成立させる。
戦争映画感は次の4軸に分解して攻める:

1. **語彙** — 動きの種類（現19モーション）を戦闘文脈込みで拡充する
2. **接続** — 任意のアクション切替がポップしない（シームレス）
3. **文脈** — 遮蔽・被弾・制圧に応じた変種（塀から身を乗り出して撃つ等）
4. **生体感** — 個体差・非同期（全員が同じ位相で息をしない・撃たない）

制約（ブラウザ限界）: テクスチャVRAM予算 230MB（repack v2の検証上限）、1シート ≦ 8192px、
Phaserのスプライトはランタイムでボーンブレンドできない。

## 1. 結論: シームレスは「ベイク時に」解決する

実行時ブレンド不能はスプライトゲーの宿命だが、本作は3Dソース（Blender + mixamorig）を
持っているので、繋ぎを**焼いて**しまえる。3層アーキテクチャ:

### L1 ベイク層（Blender / scripts/soldier_pipeline/）
- **遷移クリップ自動生成**: 同姿勢のアクション対（fire↔idle 等）について、境界ポーズ間を
  四元数slerp+smoothstepで6〜10フレーム補間したクリップを機械生成しシート化する。
  Mixamoに遷移クリップが存在しなくても任意対を自給できる。
  （異姿勢間は既存のMixamo実遷移 stand↔kneel↔prone を使う。ポーズ距離が大きい対の
  機械補間は貫通・足滑りが出るため対象外）
- **ループ閉包**: idle/forward系の終端Kフレームを先頭ポーズへブレンドし、ループのポップを消す
- **新規クリップ取込**: MixamoのFBXをドロップフォルダから一括インポート→アクション改名→レンダ

### L2 ランタイム層（Phaser / phaser_soldier_view.js）
アクション切替時の3段フォールバック:
1. ベイク済み遷移シート `trans_<from>__<to>` があれば再生してから目標アクションへ
2. 無ければゴーストスプライト（旧アクション最終フレーム）を約90msでα0へ→クロスフェード
3. 最終手段ハードカット（従来挙動）

加えて:
- **方向転換のステップ化**: 8方向スナップをやめ、45°ずつ数tick刻みで回頭（射撃目標へは即応スナップ）
- **個体desync**: ループ再生の開始位相をユニットIDハッシュでずらす+再生速度±8%ジッタ
- **変種選択機構**: `cover_fire` 等の変種シートが manifest に存在すれば自動で優先使用
  （アセットが届いた瞬間に有効化される。コード変更不要）

### L3 文脈層（ゲームロジック）
- 遮蔽中の射撃 → cover_fire 変種+ヘックス縁（射線方向）への寄りオフセット+銃口炎位置補正
- 被弾 → フリンチ one-shot（クリップ到着まではクロスフェード+姿勢一段下げで代用）
- 制圧 → cower 変種（現状は kneel/prone 代用中）
- 将来: 分隊躍進（bounding overwatch）等の分隊振付は sim_leader 側の仕事とし、本計画の範囲外

## 2. 「Mixamoリグの限界」への回答

リグ（mixamorig 33ボーン）自体は標準的で問題ない。限界の実体は
①クリップ間の繋ぎが提供されない ②カバー・軍事系の語彙が薄い、の2点。

| 課題 | 解決レーン | 状態 |
|---|---|---|
| 繋ぎが無い | L1遷移ベイクで自給 | 本計画で実装 |
| カバー語彙が薄い | クリップ追加 + Blender手調整（spine回転でlean変種を自作） | フェーズ2 |
| それでも無い動き | Cascadeur等で自作アニメ | 最終手段（当面不要） |

## 3. パイプライン（scripts/soldier_pipeline/）

ワンコマンド増分ビルド: `python scripts/soldier_pipeline/sp_pipeline.py`

```
master blend（sprite_sheet_multi_motions_2.blend、不可侵）
  → work.blend へコピー
  → sp_import_fbx.py   : ドロップフォルダのFBX一括取込（アクション改名・ボーン整合検証）
  → sp_bake_transitions.py : transitions.json の指示で遷移生成+ループ閉包
  → sp_synth_clips.py  : synth_clips.json の指示でアーマチュア直接操作による新規クリップ合成（§7）
  → sp_render_frames.py : SpriteCamで 400×262 × 8方向 × フレームを増分レンダ
  → sp_compose_sheets.py : PILで 列=フレーム/行=方向 のシートへ合成（旧シートと同一レイアウト）
  → repack_soldier_sheets_v2.py : クロップ・スケール正規化・manifest v2 再生成（既存流用）
```

検証ゲート（反ハッタリ）:
- **パリティテスト**: 新レンダの stand_idle f1 × 8方向 を旧シートのセルと画像diff
  （カメラ・方向行順・スケールの同一性を機械証明。合格するまで新旧シート混在禁止）
- repack組込の manifest整合・方向多様性md5・VRAM上限チェック

## 3.5. 自給できる動きとDLが必要な動きの線引き（2026-07-30 確定）

`sp_synth_clips.py`（§7）の導入で、**既存19モーションの組み替えで作れる語彙はDL不要**になった。
線引きは「必要な関節軌道が既存クリップの中に在るか」で決まる。

| 動き | 自給可否 | 手段 |
|---|---|---|
| 物陰に潜む（壁貼り付き） | ✅ 自給 | Idle を hold + 脊椎を屈曲 offset |
| 物陰から乗り出して射撃 | ✅ 自給 | Fire に**ロール(Z)** offset。ピッチ主導は不可（照準が壊れる） |
| 撃ってまた隠れる | ✅ 自給 | 上2つを端点にした splice 遷移（往復2本） |
| 飛び込み伏せ・回避 | ✅ 自給 | `Stand_To_Kneel`+`Kneel_To_Prone` を splice → retime 圧縮 |
| 制圧下で縮こまる | ✅ 自給 | Idle を hold + 強めの屈曲 offset |
| 被弾フリンチ | ✅ 自給 | Idle に pulse エンベロープで後方インパルス |
| **リロード** | ❌ **DL必須** | 手・指の軌道が既存クリップに一切無い。合成では作れない |
| **走り（本物の走行周期）** | ⚠️ 近似のみ | `Forward` の retime は歩調のまま速くなるだけ。接地感を出すならDL |
| 乗り越え・負傷歩き・合図 | ❌ DL必須 | 同様に元軌道が無い |

したがって §4 のDLリストは**優先度Aが「リロード」と「走り」の2本に縮小**した（Cover系とHit系は自給済み）。

## 4. モーション拡充リスト（Mixamo、フェーズ2 = 要ユーザーDL）

DL共通設定: **同一キャラ**（従来と同じ）、**Without Skin**、30fps、移動系は In Place ✓。
（Mixamoはカタログ名がログイン後でないと確認できないため、検索語で指定。
見つからない場合は §2 の手調整レーンで自作する）

### 優先度A — 戦闘の芯
| 欲しい動き | Mixamo検索語 | 用途 |
|---|---|---|
| 走り（現forwardは歩調が歩き） | "Rifle Run" / "Run" | 移動命令・躍進。歩/走の2速化 |
| リロード（3姿勢） | "Reload" / "Reloading" | 射撃ループの合間に挿入=戦闘の呼吸 |
| 被弾リアクション | "Hit Reaction" / "Impact" | 命中の視覚言語。死亡と非死亡の区別 |
| カバー（壁貼り付きidle/身を乗り出して射撃） | "Cover" / "Crouch Cover" | L3遮蔽表現の本命 |

### 優先度B — 語彙の厚み
| 欲しい動き | Mixamo検索語 | 用途 |
|---|---|---|
| しゃがみ走り | "Run Crouching" / "Crouched Walk" | 被制圧下の移動 |
| 負傷歩き | "Injured" / "Wounded" | HP低下の常時表現 |
| 指差し・合図 | "Pointing" / "Hand Signals" | **分隊長の伝達表現（North Starの伝達コストの画）** |
| 飛び込み伏せ | "Dive" | 着弾回避の緊急動作 |
| 乗り越え | "Vault" | 塀・障害物の通過 |

### 変種フックの命名規約（L2/L3、2026-07-21 実装済み）

L3 文脈層の変種は、**そのアクションシートが manifest に存在した瞬間に自動で有効化**される
（コード変更不要）。map.json に下記の正準名で記入すれば `phaser_soldier_view.js` の
フックが拾う。存在しなければ基本形へ自動フォールバック（今の19モーションで無害に動く）。

| 文脈トリガ | 期待アクション名（`<姿勢>` = stand/kneel/prone） | map.json 記入例 | フォールバック先 |
|---|---|---|---|
| 遮蔽中の射撃（cover≥0.3） | `<姿勢>_cover_fire` | `Stand.Cover_Fire` | `<姿勢>_fire` |
| 重制圧下の静止（pinned相当） | `<姿勢>_cower` または `cower` | `Kneel.Cower` | `<姿勢>_idle` |
| 被弾フリンチ（新規被弾を検知） | `<姿勢>_hit` または `<姿勢>_flinch` | `Stand.Hit` | 姿勢一段低下で代用 |

遮蔽射撃は変種の有無に関わらず、射線方向へ ~2.5px（表示20px基準）身を乗り出す縁寄せ
オフセットが即時に効く（`COVER_LEAN_PX`）。本体スプライトのみ動かし影は接地させる。

## 5. レンダ較正の正（2026-07-20 実測確定）

旧19シートのレンダパラメータは保存されておらず（カメラ2台とも現状値では不一致）、
数値解析で復元した。**この値が今後の全レンダの正**（config.json の render_args）:

- カメラ: `SpriteCam`（loc (0,-5,1.2), rot X=80° — 仰角約10°の低目線）に
  **`--ortho-scale 4.67 --shift-up 0.43`** を適用 → 旧シートと bbox 1px 一致
- 方向回転: **`--rot-sign -1`**（時計回り）。行順は 0=S,1=SW,2=W,3=NW,4=N,5=NE,6=E,7=SE
  = phaser_soldier_view.js の実測マッピング row=(8-k)%8 と互換（prone 8方向の目視で確認済み）
- セル 400×262 / 列=フレーム / 行=方向 / Eevee / 透過背景
- 注意: 旧シートとのピクセル完全一致は不可能（シートレンダ後にアクションデータが
  変化していた）。よって 2026-07-20 に**全シートを新パイプラインで再生成**し自己整合させた。
  旧シートは sheets_dir/archive_pre_pipeline_20260720/ に退避
- repack は `--char-h 72`（旧108）: 表示は manifest.charH 正規化で不変、VRAM を約半減し
  フェーズ2の増枠を確保（表示20px基準で3.6倍オーバーサンプル維持）

## 7. クリップ合成レーン（`sp_synth_clips.py` / `synth_clips.json`）

2026-07-30 追加。**アーマチュアを直接操作して既存アクションから新規クリップを作る**レーン。
`sp_bake_transitions.py` のポーズ入出力プリミティブ（`sample_pose`/`write_pose`/`blend_pose`/
`slerp_q`）を import して再利用しており、二重実装は無い。

### 演算子

ポーズ列 = `list[bone -> (location, quaternion)]`。`source`（単一クリップ）または `splice`
（複数クリップ + slerpブリッジ）で列を作り、`ops` を記載順に適用する。

| op | 用途 | 主パラメータ |
|---|---|---|
| `retime` | 速度変更・尺の圧縮 | `rate` または `frames` |
| `offset` | ボーン加算回転（lean/twist/屈曲の本体） | `bones`（度数XYZ）, `space`, `envelope` |
| `root` | 位置オフセット（弾道・寄り） | `bone`, `translate`, `envelope` |
| `hold` | ポーズ固定（+`breathe` で微動） | `frames`, `at`, `breathe` |

エンベロープは `const` / `ramp_in` / `ramp_out` / `ramp` / `pulse`。重みは恒等回転からの
slerp で効かせるので、途中の重みでも破綻しない。

**先に定義したクリップを後続クリップの入力にできる**（遮蔽ポーズ → その往復遷移を1ファイルで
書ける）。禁止しているのは自己参照のみ。

### 軸較正（実測。推測で書かないこと）

`Spine`/`Spine1`/`Spine2`/`Neck`/`Head` のローカル軸は **X=前傾ピッチ / Y=捻り /
Z=右肩側へのロール**。軸間クロストークはほぼ0（X操作時の横変位 ≤0.001）。
`Hips` だけは軸が混ざるので lean には使わない。肩・腕は体軸非整列かつ**小銃の保持が崩れる**
ので触らない。

### 踏んだ罠（2枚のレンダで実際に外した。再発防止は `tests/test_soldier_synth_clips.py`）

1. **角度を「頭部の変位量」から見積もると必ず過大になる。** 脊椎チェーンのピッチは視覚的に
   複合する。累積30°の前傾は「壁に隠れる」ではなく「崩れ落ちる」絵になった。
   落とし所は累積ピッチ Cover_Idle ≈12°(+頭8°) / Cower ≈21°(+頭12°) / Cover_Fire ≤5°。
2. **乗り出しはピッチではなくロール(Z)で作る。** ロールは小銃を肩付けしたまま横へ出るので
   照準の絵が保たれる。ピッチを足すと構えが解けて**改善ではなく劣化**になる。
3. **被弾フリンチを `*.Dying` から切り出してはいけない。** Dying は初動で小銃を手放すため、
   掠っただけで銃を投げ捨てる絵になる。代わりに Idle へ `pulse` で後方インパルスを与える
   （手のボーンを触らないので小銃は握ったまま）。
4. **レンダ job の `step` は必ず 1。** 合成側で既に間引いているため、二重間引きになる。
5. `defineAnimations()` のループ判定は語尾正規表現。新語彙を足すときは
   「持続状態＝ループ」「一回性＝非ループ」の分類を確認する（`_cower` はループ側へ追加した）。

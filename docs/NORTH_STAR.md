## 1. ゲームの核 — 一文

> **プレイヤーは全能の操縦者ではない。伝達コストと部下の癖に縛られた、一人の分隊長である。**

兵士の個性は、あなたが指示を出していない時間にこそ現れる。
RTwP（リアルタイム＋ポーズ）は個性を**見えるもの**にし、命令伝達コストは個性を**頼るしかないもの**にする。

**ショートハンド**: Close Combat（RTwP分隊リアリズム・制圧・士気） × Darkest Dungeon（ロスターへの愛着・死の不可逆・ラン構造）

**ターゲット**: WW2戦略ゲーム好き × ローグライク好き、30〜40代男性。

### North Star テスト（全設計判断の最終審査）

1. **兵士が死んだとき、リセットせずに「あいつの分まで」と続けたくなるか？**（愛着 × 納得感 × ラン構造）
2. **敗走した直後に「もう1ラン」と思えるか？**（テンポ × リプレイ性）

新機能・変更は必ずこの2問に照らす。どちらにも寄与しないものは追加しない。

## 2. 四本柱と測定基準

| 柱 | 定義 | 測定基準（プレイテストで確認） |
|----|------|------|
| **P1 個性** | 兵士1人1人が観察可能な「癖」を持つ | 2戦闘後、プレイヤーが3名以上の兵の行動傾向を言葉で説明できる |
| **P2 リプレイ性** | ラン毎に違う分隊・違う物語 | 変動源（マップ/採用/鹵獲/負傷/イベント）が毎ラン体感で違う編成判断を強いる |
| **P3 テンポ** | v1_8_1 の軽快さを裏切らない | 起動→戦闘60秒以内・強制待機1.5秒以下・standard規模で55fps以上 |
| **P4 戦略性** | 撃ち合いではなく機動と判断が勝敗を決める | 正面撃ち合いは膠着し、包囲/制圧/資源管理で崩すのが最適解になる |

### v1_8_1 の教訓（P3 の根拠）

初期衝動版は **44KB 単一HTML** だった。テンポの正体は:
- 起動即戦闘（ビルドなし・ロードなし）
- **アニメがロジックを待たせない**（1アクション40〜200msのビート）
- AUTO PILOT で戦闘が「流れる」

現行版の `await` アニメチェーン（`actionAttack` 完了待ち等）は、重さと並行バグの共通根。
**v2 では「シミュレーションは決して描画を待たない」を鉄則とする**（§5 実装戦略）。
v2 の RTwP とは、v1 の AUTO PILOT を常時化し、介入をポーズと命令に集約したものである——これが v1 のテンポと RTwP の合流点。

## 3. コア戦闘モデル v2（RTwP仕様）

### 3.1 基本構造

| 項目 | 決定 |
|------|------|
| 時間 | 固定tick（100ms）のリアルタイムシミュレーション。ポーズ無制限（アクティブポーズ）。速度 1x/2x |
| 空間 | **hexグリッド維持**（既存の地形・LOS・経路資産を再利用。離散位置で十分リアリズムは出る） |
| 指揮規模 | **1個分隊 8〜12名**（+セクター進行で増強）。小隊規模は将来拡張 |
| 経済 | AP経済は**退役**。新経済 = **時間・弾薬・士気・命令伝達** |
| 兵士 | 状態機械: `idle / move / engage / suppressed / pinned / reload / switch / assault / rout` |
| 行動時間 | 全行動に実時間コスト（照準・連射間隔・装填・**持ち替え数秒**）。瞬間スワップ廃止 → 装備乱発はシステムごと消滅 |

### 3.2 膠着の設計（塹壕戦の手触り）— P4 の核

**遮蔽下の敵は撃っても当たらない。だが制圧はできる。** 火力は「殺す道具」ではなく「動きを止める道具」。

```
pHit(1バースト) = base(武器,距離) × 姿勢 × 遮蔽 × 自己制圧 × 技能 × 疲労
```

- 有効射程・遮蔽下の基礎命中: **2〜6%/バースト**（意図的に低く）→ 対峙 = 散発的な撃ち合いで膠着
- ごく低確率の決定打（狙撃手トレイト・照準射撃で微増）は残す——「戦場の理不尽」の演出
- 各バースト（至近弾含む）は対象に**制圧値**を加算。制圧ゲージ 0–100、静穏3秒後から減衰:
  - **50+ suppressed**: 命中・移動意欲ペナルティ
  - **80+ pinned**: 移動・射撃をほぼ停止（自衛のみ）
  - pinned + 損害 → 士気崩壊チェック → rout（敗走）
- **殺傷ベクトル**（優先度順に設計。正面撃ち合いでは死なない）:
  1. **側面/背面射撃** — 遮蔽無効化で pHit ×5〜10。機動こそ殺傷力
  2. **手榴弾・迫撃砲** — 面制圧・遮蔽ごと排除
  3. **突撃（assault）** — 至近戦。対象が pinned なら圧倒的有利、そうでなければ自殺行為
  4. **開豁地移動への持続射撃** — MGの存在意義
  5. **消耗** — 弾切れ・士気切れによる後退・降伏

### 3.3 射撃規律と弾薬経済

兵/班単位の射撃モード: `hold（射撃禁止） / aimed（低速・節約・高精度） / suppress（高速・浪費・制圧特化）`

- suppress は小銃で約1弾倉/40秒を燃やす。**弾薬携行量（既存 loadout_weight の重量トレードオフ）が戦略資源になる**
- 弾薬補給 = 同一hex受け渡し（実装済 `FEATURE_SAME_HEX_TRANSFER`）+ 弾薬手ロール
- 敵も有限弾（QUALITY_DIRECTIVE WS-3 提案4を採用）

### 3.4 命令と伝達コスト — 本作の独自性

命令はいつでも出せる（ポーズ中含む）が、**兵に届くまで遅延がある**:

| 経路 | 遅延（初期値） |
|------|------|
| 接敵前の事前計画（作戦フェーズ） | 0秒（自由に配置・命令） |
| 分隊長から2hex以内 + LOS（声・手信号） | 1秒 |
| 同一班内（班長経由） | 2秒 |
| 他班・遠隔（伝令の抽象化） | 距離×1秒/hex |
| 無線手のいる班 | 固定3秒 |
| **分隊長死亡** | 全遅延×3、指揮継承まで30秒のショック |

- 指揮接続グラフは **battle_cloud.js のクラスタ計算を流用**（REDESIGN⑤「指揮網」構想をここへ統合）
- 帰結: 接敵前の計画は無料、戦闘中の変更は高価。**分隊長の位置取り自体が戦術**になる
- 命令が届くまでの間、兵は**自分のトレイトに従って行動する**（§4）——伝達コストが個性を「頼るしかないもの」にする仕組み
- **分隊長の采配**（2026-07-03 ディレクター発案）: 射撃統制コマンドを命令の主要語彙とする — **集中射撃**（「全員であのMG手を狙え」）と**射撃分配**（「お前は右から2番目」）。采配スタイル自体が将来の NCO 個性の軸（集中型/分配型の下士官）。集中射撃のアルファストライク化への対策はバランス側で担保（要critic検証）

## 4. 兵士個性システム — P1 の実装

### 4.1 トレイト = AI行動ポリシーの差分

トレイトはステータス補正ではなく、**無命令時間の行動差**として実装する（RTwPだから見える）:

| トレイト例 | 観察可能な行動 |
|-----------|--------------|
| 攻撃的 | 命令なしで交戦距離+2hexから撃ち始める。既定suppress。弾を浪費 |
| 慎重 | 遮蔽から遮蔽へしか動かない。直接命令なしに突撃しない |
| 冷静（古参の勘） | 有効射程まで撃たない。制圧下でも精度低下が小さい |
| 臆病 | 制圧閾値が低い（40でsuppressed）。だが生き残る |
| 鷹の目 | 照準射撃時、低確率決定打が2倍 |

- 各兵 2〜3個。採用時に1個は開示、残りは**戦闘で発現して判明**（発見の演出）
- 実装は「AI方針パラメータ表 + 発火ログ/吹き出し」——**必ず可視化する**。見えない個性は存在しないのと同じ

### 4.2 成長と傷跡

- XP → 既存SKILLS からのパーク選択（維持）
- **負傷の持続**（WILDFROST案4採用）: 戦闘後も残る負傷状態がロスター管理を生む
- **戦闘中のHP回復は存在しない**（2026-07-03決定・リアリズム）: sim_core に回復コードパスを置かない。回復は戦闘間のロスター管理（負傷回復判定）でのみ扱う
- **重傷状態**（QUALITY_DIRECTIVE WS-3 提案3採用）: HP<25%で行動制限+治療対象ハイライト。即死の前にドラマを作る。※無回復原則下での「治療」の再定義（安定化＝悪化停止のみ、HP非回復）は未決 — §10 Q5
- **補充兵ペナルティ**（同 提案2採用）: ベテランの死は取り返しがつかない
- 記章: 戦闘ログから自動生成される戦績（「MG陣地を制圧し続けた」等）+ 微小バフ。戦死ナラティブ（実装済）と対になる

### 4.3 装備カスタマイズ

- PL由来の武器・弾薬互換データ（構築済パイプライン）が深度の源泉。**新規データ開発は凍結し、活用に回る**
- 重量 vs 機動・携行弾数のトレードオフ（loadout_weight 実装済）が §3.3 の弾薬経済と直結

## 5. ローグライク構造 — P2 の実装

- **1ラン** = 1個分隊でセクター群を進む既存キャンペーン構造を維持。死は永続
- **採用ドラフト**（REDESIGN② S/M 採用）: 候補6枚、武器系統・トレイト・経歴を開示して「編成思想」を選ばせる
- **鹵獲系譜**（REDESIGN① S/M 採用）: 融合のランダムブーストを廃し、実在武器→鹵獲呼称→改造のトレードオフ系譜に置換。SF色はWW2語彙（鹵獲改造・闇市調達）でラップ（QUALITY_DIRECTIVE 提案6採用）
- 支援カードは「**大隊支援要請**」（砲撃・航空・補給投下）として再ラップ。リアリズム85% / SF15% の15%はここと鹵獲系譜に封じ込める
  - SF要素は**レイヤーとして後付け可能な構造を保つ**（2026-07-02決定）: 支援要請・鹵獲系譜はデータ駆動の拡張点として分離しておき、物足りなければブランチ/レイヤーで足す。コアには混ぜない
- 目標時間: **1戦闘 10〜15分、1ラン 2〜3時間**（2026-07-02確定）
- **想定プレイ文脈 = 就寝前の1戦**（2026-07-02確定）。派生要件:
  - セッション単位は「1戦闘」。**戦闘間オートセーブ・即再開**は P3 の必須要件（ランを数日にまたいで消化できること）
  - 1戦闘は15分で必ず畳める（膠着が延々続かないよう、弾薬・士気・増援の時計で決着圧力をかける）

## 7. 実装戦略 — Strangler Fig（絞め殺しの木）

現行 logic_game.js の戦闘コアを**書き換えない**。新しい sim コアを別モジュールとして育て、接ぎ木し、旧コアを段階退役させる。

### 7.1 モジュール構成

| 新モジュール | 責務 | 依存 |
|------------|------|------|
| `sim_core.js` | tick・状態機械・射撃/制圧/士気解決 | **純JS・Phaser非依存・ヘッドレス実行可**（node でユニットテスト可能に） |
| `sim_orders.js` | 命令キュー・伝達遅延・指揮グラフ | battle_cloud.js のクラスタ計算を流用 |
| `sim_policy.js` | トレイト→無命令時行動ポリシー | sim_core のみ |
| `dev_sim.html` | **v1流の軽量デバッグハーネス**（canvas直描き・44KB精神）。sim_core を Phaser なしで回して手触りを検証 | sim_* のみ |
| phaser_bridge 拡張 | sim_core イベント→既存VFX/スプライト | 検証後に接続 |

### 7.2 再利用マップ（資産は捨てない）

- **そのまま使う**: logic_map.js（hex/LOS/A*）、data/ PL武器・弾薬マスタ、loadout_weight.js、phaser_terrain/vfx/unit/sound、logic_campaign.js（ラン構造）、phaser_sidebar.js
- **流用・変形**: battle_cloud.js（→指揮網）、logic_ai.js の地形スコアリング（→sim_policy）
- **段階退役**: logic_game.js のターン処理・AP・`isProcessingTurn`・awaitアニメチェーン

### 7.3 鉄則

1. **シミュは描画を待たない。描画はシミュを止めない**（v1の教訓の技術的表現）
2. sim_core は**副作用のない純関数評価**で意思決定する（swap試行→戻す、のような破壊的プローブ禁止）
3. 数値は全て `SIM_TUNING` テーブル（data.js）に集約。マジックナンバー禁止
4. 各ワークストリームは独立ファイルで境界明確に（並列委譲の前提）

### 7.4 Vertical Slice v2.0 — 受け入れ基準

固定マップ1枚・自分隊9名 vs 敵12名で、以下を**全て**満たしたらスライス完成:

1. 遮蔽で対峙する両軍が、無操作で3分以上膠着する（双方死者1名以下、散発射撃と制圧ゲージが観察できる）
2. 側面機動で膠着が破れる（包囲による無損害勝利が成立する）
3. ポーズ→命令→解除で、命令が伝達遅延後に実行される（近傍1〜2秒、遠隔班5秒+）
4. 兵士2名以上が無命令時間にトレイト由来の異なる行動を取り、ログ/吹き出しで可視
5. 装備変更ログ ≤ 2回/兵/戦闘
6. 55fps以上・強制待機1.5秒以下

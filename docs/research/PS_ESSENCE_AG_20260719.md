## 2. 全体アルゴリズムの解剖
*   **ターン/フェーズ構造**: 1ターンはゲーム内時間で1分をシミュレートする。大きく「Order Phase（命令フェーズ）」と「Combat Phase（戦闘フェーズ）」に分かれる。戦闘フェーズはさらに3つのシーケンスと複数のサブシーケンスに細分化されており、交互ではなく疑似的な同時解決（インパルス制に近い）を行うことで流動的な戦闘を表現している。
*   **射撃解決**: 250種類以上の兵器データテーブルに駆動される。命中率は距離による減衰、ターゲットの姿勢、地形の遮蔽などを考慮して算出。また、装甲厚と貫通力の比較テーブルが精緻に計算される（テーブル駆動の度合いが極めて高い）。
*   **士気・抑圧**: （推測を含む）被弾や至近弾により抑圧（Suppression）が蓄積し、ピンダウン（Pin down: 移動・射撃制限）や敗走（Rout）状態へと遷移する。後述の指揮範囲内にいることで士気が向上・維持される仕組みを持つ。
*   **視認・隠蔽**: スクエアグリッド（四角形マス）を採用。詳細なLine-of-Sight（視線）判定があり、発砲による隠蔽の喪失や、地形（茂み・建物・夜間・煙）による視認の遮りが実装されている。
*   **指揮系統 (Command Radius)**: 高位の指揮官は「Command Radius（指揮範囲）」を持つ。この範囲内にいるユニットは士気や戦闘効率にボーナスを得る。また、この範囲はスペースキーで視覚的にハイライト（可視化）することが可能。指揮官から離れた部隊が機能不全に陥る（命令遅延や士気崩壊）ことを抽象化した核となるメカニクスである。
*   **経験・ベテラン化**: キャンペーンモードでは、生き残った部隊が経験を積み、次のシナリオ（戦闘）に引き継がれる。
*   **シナリオ/キャンペーン生成**: 強力なエディターが付属しており、プレイヤーが独自のマップ、部隊編成、キャンペーンを作成できる。

## 3. squad_tactics への移植候補 (優先度付き)

1. **Command Radius（指揮影響範囲）の可視化と微小士気ボーナス** (優先度: 高)
   * **接続先**: `sim_orders.js` / `sim_core.js` (NORTH_STAR §3.4 伝達コスト) / Phaser UI
   * **内容**: NORTH_STARの「分隊長から2hex以内（遅延1秒）」というルールを、PSのようにUI上で明確に可視化する。例えば、プレイヤーが分隊長を選択した際、またはAltキーを押した際に、影響範囲のHexがハイライトされるようにする。これにより、30hexのビネット規模において「分隊長の位置取り」という戦術パズルを視覚的に支援する。また、範囲内の兵士の制圧ゲージ（Suppression）減衰速度にボーナスを与え、NCOの近くにいる安心感（士気）を表現する。

2. **発砲による暴露（Spotting）のリスク化** (優先度: 中)
   * **接続先**: `logic_map.js` (LOS) / `sim_core.js`
   * **内容**: 射撃規律（hold/aimed/suppress）に応じて被発見確率を変動させる。suppress（浪費）はマズルフラッシュと音で即座に暴露されるが、aimed（照準射撃）は一定確率で隠匿を保てるようにする。NORTH_STAR §3.2 の「遮蔽下の敵は当たらない」という膠着設計に対し、「誰が先に撃って位置を晒すか」という駆け引きを追加する。

## 4. 頂戴しないもの

*   **四角形グリッド (Square Grid)**: 本作はHexグリッド（HEX_SIZE=54）で構築済み（NORTH_STAR §3.1）であり、移植すると基盤が崩壊するため採用しない。
*   **250種以上の詳細な兵装・装甲貫通テーブル**: 30hexの分隊戦術・歩兵戦主体のスケールにおいては帳簿管理過多となる。本作の武器データはPL由来（`data.js` / `loadout_weight`）で充足しているため、PSのデータテーブルは持ち込まない。
*   **複雑なサブシーケンス型ターン解決**: NORTH_STAR §3.1 の「固定tick（100ms）のRTwP」と真っ向から衝突し、P3（テンポ）を損なうため不採用。
